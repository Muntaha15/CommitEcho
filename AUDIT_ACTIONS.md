# CommitEcho audit action list

Updated 2026-09-27. This combines the repository audit, the follow-up review, and the pasted audit report. Priorities describe the order for reaching the documented v0.1 release gates. Items marked **P0** block a usable or trustworthy release; **P1** should be fixed before real client trials; **P2** closes remaining documented behavior and maintenance gaps. Each item includes the check that makes it done.

The current architecture—private SQLite drafts, Git-tracked records and trailers, and a rebuildable SQLite search index—is suitable for v0.1. Repair the existing boundaries before adding new storage or services.

## P0 — Release blockers

1. [x] **Make the MCP server launch.** `python -m commitecho serve --repo .` currently exits with `Got unexpected extra argument (serve)`, and setup generates that command. Register `serve` on the actual Click entry point. Check the documented command, generated client command, and a real MCP initialize/list-tools exchange. [Entry point](src/commitecho/__main__.py#L36), [setup command](src/commitecho/transports/cli.py#L507), [README](README.md#L107).
2. [x] **Verify the record that Git actually contains.** Read and validate the committed JSON blob, its schema/version and record ID, expected parent, and code fingerprint. Persist a digest of the prepared record and compare it with the committed content when local draft data exists; define an honest exact result for a fresh clone without that database. A test that edits the prepared JSON before committing must never return `exact` (it does today). A Git read failure must return `unverifiable`, not an empty manifest. [Verification](src/commitecho/application/verify.py#L85), [Git reads](src/commitecho/git/adapter.py#L312).
3. [x] **Make capture and prepare atomic, including idempotency.** Check the full request payload, perform all SQL writes and the conditional revision-counter update in one transaction, and record the operation's original response only when the transaction succeeds. Remove helper-level commits that break the transaction. Account for the prepared file write and recovery after a crash. Tests must cover failed retries, changed content under the same operation ID, concurrent writers using the same expected revision, and replay after later operations. [Operation log](src/commitecho/storage/repository.py#L271), [capture](src/commitecho/application/capture.py#L148), [prepare](src/commitecho/application/prepare.py#L67). This also fixes `begin_change` replay by title, `record_decisions` replay returning all revisions, and `prepare_commit` replay selecting the latest record.
4. [x] **Fail closed when a history anchor cannot be resolved.** An invalid `at_ref` or failed reachability lookup currently makes the empty set admit every indexed branch. Return an error or empty results with partial coverage. Test invalid refs and Git history failures alongside normal branch isolation. [Search scope](src/commitecho/application/retrieve.py#L55), [result filter](src/commitecho/application/retrieve.py#L123).
5. [x] **Make indexing recoverable and validate records before publishing them.** Index every record for a commit and mark that commit complete in one transaction. Retrying after a missing blob, malformed JSON, or interrupted insert must revisit the commit; `coverage: full` must mean its records were handled. Validate the portable record schema and identity, and retain diagnostics for invalid records. [Index loop](src/commitecho/transports/cli.py#L245), [record insert](src/commitecho/transports/cli.py#L301).

## P1 — Data integrity and core recall

6. [x] **Fix file-path indexing and rebuild existing indexes.** Portable decisions store paths in `code_scope.paths`, while the indexer reads a nonexistent top-level `paths`. Test `search_history(path=...)` and `compare_history(path=...)` after a full rebuild. [Indexer](src/commitecho/transports/cli.py#L345), [model](src/commitecho/domain/models.py#L163).
7. [x] **Give submitted evidence a usable identity and validate links.** `record_decisions` generates evidence IDs without returning a mapping or accepting caller IDs, leaving same-call decision references unusable. Include evidence referenced by alternatives, reject missing or foreign IDs, expose evidence IDs in search results, and make fresh-clone `get_evidence(evidence_id=...)` read committed records. Test capture, prepare, clone, and retrieval together. [Capture](src/commitecho/application/capture.py#L175), [prepare](src/commitecho/application/prepare.py#L128), [retrieve](src/commitecho/application/retrieve.py#L169).
8. [x] **Enforce provenance at the MCP trust boundary.** Agent-supplied evidence currently accepts `developer_confirmed`, `independent_artifact`, `source_adapter`, and `developer_attestation` labels directly. Keep agent claims labelled `agent_reported` until an actual independent source or developer action establishes stronger provenance. Test that a tool caller cannot self-assert confirmation. [Capture](src/commitecho/application/capture.py#L178), [input](src/commitecho/transports/mcp_server.py#L43).
9. [x] **Preserve the decision revision graph in portable records.** Preparation always serializes empty `predecessor_revision_ids`, although predecessors are stored in the draft database. Query and publish the actual links; test a superseding decision after a fresh clone. [Preparation](src/commitecho/application/prepare.py#L242), [storage](src/commitecho/storage/repository.py#L221).
10. [ ] **Model repeated record and revision associations.** The index has one `commit_oid` per record and one `record_id` per revision. A cherry-pick/rebase can reuse a record, and one revision may be selected for several commits. Keep record content by ID and store separate commit–record and record–revision associations. Test two records using one revision and one record present in two commits. [Schema](src/commitecho/storage/migrations.py#L137), [insert](src/commitecho/transports/cli.py#L305).
11. [ ] **Reject cross-change and cross-worktree selections.** `prepare_commit` loads revisions and evidence by ID without proving ownership by its `change_id`; `begin_change` can resume a change from another worktree. Enforce the intended ownership in the existing queries and test both cases. [Preparation](src/commitecho/application/prepare.py#L118), [resume](src/commitecho/application/capture.py#L83).
12. [x] **Propagate Git errors and handle SHA-256 roots.** The staged and committed diff readers turn Git errors into empty changes; root diffs hardcode the SHA-1 empty tree even when object format is SHA-256. Use the repository's object format and report failed reads. Test normal, root, and SHA-256 commits. [Git adapter](src/commitecho/git/adapter.py#L145), [committed diff](src/commitecho/git/adapter.py#L312).
13. [ ] **Put a bound and disclosure check on portable content.** The model's 4 KiB `max_content_bytes` claim is unenforced, the actual per-evidence cap is 64 KiB, and the whole record has no bound. Define/enforce the intended limits; reject or clearly flag likely credentials and private paths before writing shareable JSON. Test size and sensitive-content cases. [Evidence model](src/commitecho/domain/models.py#L129), [record write](src/commitecho/application/prepare.py#L187). Redaction is best effort and must not silently change the meaning of a decision.
14. [ ] **Run a live workflow for each supported client.** Existing acceptance tests vary only a client string and call services directly. Record client/version, verify generated configuration, MCP handshake, capture, prepare, commit, verify, clone, and recall for Codex, Antigravity, and Copilot VS Code. [Acceptance tests](tests/integration/test_acceptance.py#L1), [release gates](README.md#L243).

## P2 — Contract, operations, and maintenance

15. [ ] **Define and implement change completion.** `verify_commit` never sets `committed`, so completed work stays `prepared` in status. Specify how a multi-commit change remains open for its next commit and when it is finally closed; report abandoned changes separately. [Preparation](src/commitecho/application/prepare.py#L176), [status](src/commitecho/application/retrieve.py#L348).
16. [ ] **Make search inputs truthful.** `line`, `from_ref`, and `to_ref` are accepted but unused; a path is searched only if text produced no results. Implement the documented intersection/range/line behavior or reject unsupported combinations. Bound and stabilize pagination, then test each advertised filter. [Search](src/commitecho/application/retrieve.py#L32).
17. [ ] **Distinguish ordinary supersession from branch conflict.** The current detector calls any two revisions of one decision a conflict. Use predecessor links and ancestry to identify unresolved branch divergence. Test linear revision and divergent-branch cases. [Conflict detection](src/commitecho/application/retrieve.py#L447).
18. [ ] **Handle ordinary text queries predictably.** Raw questions go directly to FTS5 `MATCH`; punctuation or operators can cause syntax errors or change query meaning. Define a safe literal-search rule or return a clear input error, then test punctuation and quoted text. [FTS search](src/commitecho/application/retrieve.py#L106).
19. [ ] **Use the configured Git executable throughout.** `compare_history` and the CLI indexer hardcode `git` and bypass the adapter's `COMMITECHO_GIT` override. Route ancestry, commit traversal, and blob reads through the existing Git adapter. Test with an override path. [Ancestry](src/commitecho/application/retrieve.py#L412), [index traversal](src/commitecho/transports/cli.py#L234).
20. [ ] **Make MCP tool errors recognizable to clients.** The server returns JSON text containing `is_error` for tool failures. Check the installed SDK's tool-error mechanism, use it, and test actual MCP dispatch for success, validation errors, and internal errors. Python's `except Exception` does not catch `KeyboardInterrupt` or `SystemExit`. [Tool handler](src/commitecho/transports/mcp_server.py#L135).
21. [ ] **Give draft export a defined backup format.** `export` emits SQLite rows with nested JSON stored as strings and omits linked evidence and predecessors. Decide whether it is a human-readable export or a restorable backup, document the format, and test that purpose. [Export](src/commitecho/transports/cli.py#L459).
22. [ ] **Make the evaluation checks part of the test gate.** `pytest` currently collects 78 tests and no cases from `eval_runner.py` or `baseline_comparison.py`; fixture-based checks also skip if their manifest is absent. Generate fixtures and invoke the eval scripts explicitly in CI, or make them discoverable and fail if a required fixture is absent. Do not treat the structural baseline as an answer-quality benchmark. [README](README.md#L205), [eval runner](tests/evals/eval_runner.py#L394), [baseline](tests/evals/baseline_comparison.py#L399).
23. [ ] **Track the design documents and align examples with the wire schema.** `.gitignore` excludes `docs/`, so the locally present architecture and technical notes do not travel with the project. Remove that ignore rule, review the documents before tracking them, and correct worked-example field names (`predecessor_revision_ids`, `code_scope.paths`, `content`, `evidence_id`). [.gitignore](.gitignore#L10), [design example](docs/architecture.md#L320).
24. [ ] **Keep the MCP tool schema in one place.** Input rules appear in both Pydantic models and handwritten MCP tool definitions. Derive advertised schemas from the validation models where the SDK permits; test a client sees the required fields. [Models](src/commitecho/transports/mcp_server.py#L34), [definitions](src/commitecho/transports/mcp_server.py#L243).

## Claims deliberately excluded from the required list

- The pasted report says `except Exception` catches `KeyboardInterrupt` and `SystemExit`; it does not.
- The reported pagination offset remains correct after reachability filtering. Fetching all matches and an extra empty final page are efficiency and clarity concerns, included under item 16.
- A full commit OID passed to `git log` does not justify a separate path-ambiguity task. The actual CLI issue is inconsistent Git execution and unchecked failures, covered by items 5 and 19.
- `PreparedFor` is used through `commitecho.domain.models`; no public `commitecho.domain` export is promised. Contributor boilerplate, shared test helpers, semantic search, Git notes, a web UI, transcript import, and performance rewrites can wait for a demonstrated need.

## Current validation baseline

- The existing suite passed **78 tests** on this Windows workspace using the installed Python with an absolute `PYTHONPATH` and a writable pytest temporary directory.
- Targeted disposable-repo checks reproduced false `exact` after editing committed JSON and silent replay of changed decision content.
- In-memory index checks reproduced zero indexed paths for normal records, one association for a revision reused in two records, and a result returned for an invalid `at_ref`.
- `python -m commitecho serve --repo .` currently exits before starting the server.
