# Multi-client implementation review and repair plan

Reviewed 2026-10-03 against `MULTI_CLIENT_INTEGRATION_PLAN.md`; implementation
baseline `1763d0d`. Three parallel reviews covered setup, Git hooks, and
lifecycle/plugin packaging. Shared services, transport schemas, existing
acceptance tests, and the four implementation commits were also inspected.

Locations below refer to the baseline, before repairs. P1 findings can lose user
content or defeat validation; P2 findings affect reliability, compatibility, or
the accuracy of support claims.

## Official documentation compliance

- [Codex skills](https://learn.chatgpt.com/docs/build-skills) and
  [project instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md):
  folder skills under `.agents/skills`, root `AGENTS.md`, and override precedence.
  The revised profile paths comply; discovery in each actual surface still needs qualification.
- [VS Code skills](https://code.visualstudio.com/docs/agent-customization/agent-skills)
  and [MCP servers](https://code.visualstudio.com/docs/agent-customization/mcp-servers):
  repository skill folders and `.vscode/mcp.json` server configuration.
  Current docs prefer `.mcp.json` for portability and retain `.vscode/mcp.json`
  for compatibility. Keep the planned local profile; a deliberate config-path
  migration needs ownership and coexistence handling rather than an incidental rewrite.
- [Antigravity MCP](https://antigravity.google/docs/mcp) and
  [skills](https://antigravity.google/docs/skills): workspace server config and folder skills.
  IDE and CLI acceptance remain separate.
- [Claude MCP](https://code.claude.com/docs/en/mcp): project `.mcp.json`,
  interactive approval, and `CLAUDE_PROJECT_DIR` in spawned stdio servers.
  Reading the root in Python is compliant; no speculative Codex variable is needed.
- [Claude hooks](https://code.claude.com/docs/en/hooks): current exec-form
  command/args is valid. Native deadlines and exit/output visibility matter;
  generated JSON does not prove event loading. Zero-exit stderr goes to debug
  logging, so current quiet warnings cannot establish observable native failure.
- [Claude plugin reference](https://code.claude.com/docs/en/plugins-reference):
  components outside `.claude-plugin`, authoritative `claude plugin validate`,
  followed by actual plugin-loaded MCP/skill acceptance. Installed-package
  dependency must be explicit; an absolute interpreter is a local artifact.
- [Git hooks](https://git-scm.com/docs/githooks) and
  [configuration](https://git-scm.com/docs/git-config): `commit-msg` receives
  one message-file argument, nonzero rejects, `core.hooksPath` controls the
  effective directory, and `--no-verify` bypasses this local policy.
- [Git commit](https://git-scm.com/docs/git-commit): amend reuses the existing
  commit's parents. A message-file-only hook cannot infer the prospective parent
  reliably. Existing capture/preparation targets HEAD, so automatic amend support
  must not be claimed.
- [Git trailer parsing](https://git-scm.com/docs/git-interpret-trailers): use
  `--parse --no-divider` for complete commit-message input.
- [Git diff-index](https://git-scm.com/docs/git-diff-index): use `--no-renames`
  explicitly to make manifests independent of user rename configuration.

## Repair sequence

1. Repair shared setup validation, ownership, migration, command parsing, and
   doctor. Keep the neutral skill, existing profiles, absolute local launches,
   eight tools, arbitrary client identifiers, and storage schema.
2. Repair Git gate validation and launcher/locality safety. Reuse the existing
   record validator and manifest helpers; remove duplicated warn/reject branches
   and unprovable amend exceptions. No generic hook framework.
3. Bound explicit indexing, gate unqualified native installs, preserve native
   handler neighbors during cleanup, and make plugin regeneration conservative.
4. Expand real generated-command checks to all eight tools and target worktrees;
   add actual Git rejection/preservation regressions and plugin stdio checks.
5. Run the complete project-environment suite, including real MCP handshakes.
   Record results and remaining actual-client qualification separately.

No repository commit, push, package publication, or user hook/config installation
is part of this repair. Tests use isolated Git repositories.

## Repairs implemented

- Setup/doctor now share static configuration validation and repository selection.
  Setup preserves customized launch entries and skills, uses explicit
  `--regenerate-server`, retains TOML comments, scopes exact legacy migration,
  and preflights readable assets, directory structure, and root containment.
  Quoted Windows executable paths pass actual generated stdio launches.
- The Git gate reuses full record validation, requires canonical declarations,
  checks the current HEAD/index manifest, and handles validation failures through
  one advisory/strict boundary. Strict runtime absence or missing module rejects.
  Git determines the effective hook path; both install and uninstall enforce
  locality, preserve foreign bytes, and avoid guessed amend support.
- Complete-process indexing deadlines replace the partial between-commit timer.
  The index worker closes its connection and does not open an unused drafts DB.
  Unqualified native installation is disabled before any writes; legacy cleanup
  recognizes generated handlers and preserves neighboring/customized groups.
- Plugin generation preflights every asset and refuses custom/foreign content,
  invalid output ancestors, and escaped paths. It uses installed package metadata,
  retains a minimal layout, and labels its runtime dependency explicitly.
  Local and portable generated commands each pass all-eight-tool protocol checks
  from an unrelated cwd with the documented project-root environment.
- The neutral canonical skill, eight MCP tools, provenance/revision/idempotency
  semantics, and storage schema are retained. Claude's profile identifier now
  participates in the full existing service-layer acceptance scenario.

## Acceptance gaps retained explicitly

Claude is unavailable in this environment, so `claude plugin validate`, native
event acceptance, interactive skill discovery, and cross-client fresh-chat
handoff cannot be recorded as passed. Current client versions and POSIX
qualification are absent. Do not inherit old SDK/client results as proof of
this revised integration. Generated-command smoke tests use the installed
editable project environment with no `PYTHONPATH`; a new standalone-wheel
installation and cached offline distribution test were not performed. The
default plugin is therefore described as a local installed-runtime artifact.
Automatic post-commit verification, historian,
specialized slash skills, registry-backed execution, and storage changes remain
deferred as the plan specifies.
